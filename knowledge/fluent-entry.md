# Fluent entry and expression capture

[Architecture overview](README.md)

The `fluent` feature adds value entry methods, assertion aliases, and optional expression rewriting. Fluent chains use
the same state and failure handling as macro entry.

## Borrowing and ownership

| Entry               | Ownership          | Completion                                           |
|---------------------|--------------------|------------------------------------------------------|
| `must()`            | Borrows.           | Panics on the first failure.                         |
| `must_owned()`      | Owns the receiver. | Panics on the first failure.                         |
| `verify(...)`       | Borrows.           | Returns failures from the callback's returned chain. |
| `verify_owned(...)` | Owns the receiver. | Returns failures from the callback's returned chain. |

[Borrowing and owning entry traits](../assertr/src/entry/fluent.rs) are separate. Autoref permits an owned binding to
call `must`. Reference receivers reborrow their pointee. Unsized strings and slices remain shared-reference subjects.
Owning entry on `&T` owns that reference.

Aliases follow [mechanical naming rules](../assertr-macros/src/fluent_aliases/naming.rs), such as `is_equal_to` →
`be_equal_to` and `contains` → `contain`. Explicit overrides cover names the rules cannot derive. Aliases preserve the
source method's behavior and bounds.

## Scoped expression capture

Plain fluent entry has no source-expression text. `#[assertr::fluent_expressions]` rewrites visible `must`,
`must_owned`,
`verify`, and `verify_owned` calls inside a function or inline module. It attaches the receiver tokens and supports
renamed runtime dependencies. Place it above test-style procedural attributes so it sees the original body. It cannot
see fluent calls generated by later macro expansion. Other item kinds and out-of-line modules are rejected.

Verification preserves callback call traits, inference, and function-pointer coercions. Inline closures receive the
expression before assertions execute. Callback values pass through unchanged. After the original call resolves their
type, a private type probe permits attachment only for capture-chain inputs and failures from the matching entry
location. The [macro](../assertr-macros/src/fluent_expressions/mod.rs) and
[runtime attachment helpers](../assertr/src/__private/fluent_expressions.rs) implement this split.

Fluent capture roots privately record pending attachment. Mapping and renderer changes preserve eligibility. Derivation
clears it, and `with_expression` overrides it. `AssertionFailures` retains eligible indexes privately until attachment
completes. Public fields show `None`, never a placeholder. Cloning preserves pending attachment, equality ignores it,
and owned iteration or conversion to a vector discards it.

The rewrite is based on method spelling. Unrelated verification callbacks and result types have no-op fallbacks. An
unrelated `must()` can still fail to compile when the rewrite adds `with_expression`. Keep such calls outside the
annotated scope. [Expression fixtures](../assertr-macros/tests/fluent_expressions/) pin syntax and collision behavior.
